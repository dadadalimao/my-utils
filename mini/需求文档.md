# AI 写小说工具 — 需求文档

> 版本：v0.4  
> 定位：接入 AI API 辅助写小说的小工具；前后端分离；优先打通「对话生成 → 本地保存 → 云端同步」主链路。  
> 前端形态：uni-app 一套代码多端部署（**微信小程序 / H5 / App**）。  
> 后端形态：NestJS + SQLite。

---

## 1. 产品概述

### 1.1 目标

做一个可接入多类 AI API 的写小说工具：用户通过对话生成**章节 / 大纲 / 建议**，可将章节与大纲（按章节维度）保存到本地，并支持将全部用户数据（含 API Key）上传到后端做同步与导入导出。

### 1.2 范围（本期）

| 纳入 | 不纳入（后续可扩展） |
|------|----------------------|
| 手动注册 / 登录的极简账号 | 微信一键登录、短信验证码、密码找回 |
| DeepSeek、Kimi 预设厂商与模型切换 | 任意第三方厂商自由接入 UI |
| 客户端直连厂商 API | 服务端 AI 代理转发 |
| 对话生成（章节 / 大纲 / 建议） | 多用户协作、分享公开链接 |
| 大纲结构化存储、按范围注入 AI、保存正文时自动维护章大纲 | 版本历史、分支对比 |
| 本地保存 + 云端全量上传/导入 | 用户自定义提示词模板云端市场 |
| 未登录纯本地使用 | 应用商店合规文案、用户协议（开发期暂不考虑） |
| 后端固定提示词模板下发 | 角色库、世界观库、计费统计 |
| 单用户多本书基础管理 | 微信一键登录以外的第三方登录 |
| 多端：微信小程序 / H5 / App（uni-app） | 非 uni 的多套平行前端 |

### 1.3 角色

| 角色 | 能力 |
|------|------|
| **访客（未登录）** | 配置 Key、对话生成、本地保存小说/章节/大纲；不可上传/导入云端 |
| **注册用户** | 访客全部能力 + 登录后上传/导入全量数据、拉取需登录的云端能力 |

### 1.4 技术栈（已定）

| 层级 | 选型 | 说明 |
|------|------|------|
| 前端框架 | **uni-app（Vue 3）+ Vite + TypeScript** | 一套业务代码出三端 |
| 前端状态 | **Pinia** | 小说、会话、设置、登录态 |
| 目标端 | **微信小程序、H5、App** | App 用 uni-app 打包路径 |
| 本地数据 | 存储抽象层 | 小配置用 `uni.setStorage`；章节等大体量按端选用合适方案（如 SQLite 插件），对外统一 Repository 接口 |
| AI 请求 | 客户端直连 | `uni.request`（及各端流式能力）；小程序配置 request 合法域名；H5 处理 CORS |
| 后端框架 | **NestJS** + TypeScript | 账号、全量同步、提示词模板；**不做 AI 代理** |
| ORM / 库 | **Prisma** + **SQLite** | 个人/小规模部署优先；库文件易备份 |
| 鉴权 | JWT | 登录后访问同步与需鉴权接口 |
| 接口风格 | REST（JSON） | 上传/导入为全量快照体 |

**仓库建议结构（实现时可调整）：**

```
mini/
  apps/client/     # uni-app 前端
  apps/server/     # NestJS 后端
  需求文档.md
```

## 2. 用户体系（极简）

### 2.1 注册

- 方式：**手动注册**（用户名 + 密码）。
- 校验：
  - 用户名：唯一；长度与字符集由实现约定（建议 4–32，字母数字下划线）。
  - 密码：明文传输需走 HTTPS；服务端哈希存储（不可逆）。
- 无邮箱/手机绑定要求。
- **密码找回：不支持**（丢失即无法恢复该账号云端数据访问；本地数据不受影响）。

### 2.2 登录 / 登出

- 登录成功后颁发会话凭证（Token / Session），前端持久化。
- 登出清除本地会话；云端数据仍保留在服务端；本地小说数据默认保留。

### 2.3 与数据的关系

- 所有云端数据归属 `userId`。
- **API Key、小说、章节、大纲、对话相关配置等均可上传**，按用户维度隔离。
- 未登录时数据仅存在本地；登录后可选择上传绑定到当前账号。

## 3. AI 厂商与模型

### 3.1 预设厂商

| 厂商 | 说明 |
|------|------|
| DeepSeek | 预设；支持切换该厂商下可用模型 |
| Kimi（Moonshot） | 预设；支持切换该厂商下可用模型 |

### 3.2 模型切换

- 每个厂商维护一份**可选模型列表**（可由后端配置下发，或前端写死首期列表）。
- 用户可按「当前小说 / 全局默认」选择：厂商 + 模型。
- 请求时使用用户已保存的对应厂商 API Key。

### 3.3 API Key 与调用方式

- Key **由用户自行填写**，归属该用户，本地优先缓存。
- Key **允许随用户数据一并上传到后端**（服务端加密存储）。
- **AI 调用：客户端直连厂商**（微信小程序 / H5 / App 均由客户端发起 DeepSeek、Kimi 请求）。
  - 后端**不提供** AI 补全代理。
  - 各端注意点：小程序需配置 request 合法域名；H5 注意 CORS；App 相对直接。流式输出按各端能力降级（不支持则整包返回）。

## 4. 功能需求

### 4.1 前端

#### 4.1.0 技术形态

- 采用 **uni-app（Vue 3 + TS + Pinia）**，目标端：**微信小程序、H5、App**。
- 业务逻辑与本地 Repository 与 UI 分层，避免绑死单一端 API。
- 本地存储经抽象层访问（配置类 / 小说章节类可分策略实现）。

#### 4.1.1 对话工作台（核心）

- 支持三种生成模式，可切换：
  1. **章节**：按提示生成正文章节。
  2. **大纲**：生成/细化大纲；落库时**按章节维度、可单独提取的结构**保存（见 4.1.2、4.1.6）。
  3. **建议**：写作建议、剧情方向、文风调整建议等（不强制落库）。
- 每种模式附带**对应系统提示词**（来自后端模板或本地默认）；用户可在对话中补充需求。
- 展示流式/非流式回复（优先支持流式）。
- **大纲上下文注入（类工具）**：发起对话或用户显式引用大纲时，前端按选定范围从本地组装大纲文本/结构化片段，自动附带进本次请求（系统消息或独立 context 块），无需用户手动复制粘贴。
  - 可指定范围：单章 / 连续章区间（如第 3–8 章）/ 全书大纲摘要。
  - 仅注入 `outline` 字段内容，**不默认夹带正文**，保证上下文短且可预期。
- 可将本轮结果：
  - **保存为章节正文**（写入某章 `content`；保存成功后**自动维护该章大纲**，见 4.1.6）；
  - **保存为章节大纲**（写入某章 `outline`，可新建章或覆盖；格式须符合可提取规范）；
  - 建议模式默认不自动保存，用户可复制（首期可仅复制）。

#### 4.1.2 小说与本地存储

- 支持创建 / 切换 / 重命名 / 删除小说（本地优先）。
- **章节**为基本保存单元，正文与大纲**分字段存储**（禁止把大纲只嵌在正文里导致无法单独抽取）：
  - `content`：正文章节内容；
  - `outline`：该章大纲（结构化或约定格式，见 4.1.6）。
- 章节：列表、查看、编辑、删除、排序（排序首期可简化为创建顺序 / 手动调序）。
- 须提供「仅导出/仅展示大纲」能力（按章、按范围、全书拼接），供 UI 与投喂 AI 共用同一套提取逻辑。
- 本地存储：小说与章节（含正文与章大纲）、厂商与模型偏好、API Key、对话上下文策略等。
- **未登录即可完整使用**上述本地能力（生成需已配置 Key）。

#### 4.1.6 大纲格式、提取与自动维护

**设计目标**：大纲随时能被单独抽出，并按指定章节/范围自动丢给 AI；保存正文时顺带维护对应章大纲，避免正文与大纲脱节。

1. **存储格式（便于单独提取）**
   - `outline` 与 `content` 物理分离；同步包、本地库均可按字段直接读取。
   - 建议章大纲为**结构化对象**（便于拼接与截取），展示/投喂时可序列化为纯文本。示例字段：
     - `summary`：本章一句话或短摘要（必填倾向）
     - `beats`：情节点列表（可选，字符串数组）
     - `notes`：伏笔/人物变动等备注（可选）
     - `updatedAt` / `source`：`manual` | `from_content` | `from_chat`（可选，便于排查）
   - 若首期简化为纯文本，仍须保证：**全文可按章切分、按 `order` 范围拼接**，且绝不与 `content` 混存。

2. **提取与投喂 AI（类工具）**
   - 统一方法：`getOutlines(novelId, range)` → 返回按章排序的大纲片段（含章序、标题、`outline` 序列化结果）。
   - 工作台提供范围选择：当前章 / 自定义起止章 / 全书。
   - 章节、大纲、建议模式在需要剧情连贯性时，**默认或一键**将选定范围大纲注入请求；用户可关闭本次注入。
   - 注入内容只含大纲，token 紧张时可优先 `summary`，再按需附带 `beats`。

3. **保存正文时自动维护章大纲**
   - 用户将生成结果（或编辑后正文）**保存为某章 `content`** 后，自动触发「维护该章大纲」：
     - 用当前正文（可截断）+ 既有大纲（若有）请求 AI，或用本地规则/模板生成短摘要，写回该章 `outline`。
     - 首期推荐：保存成功后自动发起一次「根据正文更新本章大纲」的轻量请求（可配置开关；失败不阻断正文已保存）。
   - 手动编辑 `outline` 始终允许；自动维护默认**覆盖 `summary`（及约定的自动字段）**，避免 silently 清空用户手写 `notes`（若字段拆分）。
   - 仅保存大纲、不改正文时：不反向改写 `content`。

#### 4.1.3 同步（上传 / 导入）

- **上传**：将当前全部本地数据打包上传至后端（需登录）。
- **导入**：从后端拉取用户数据写回本地（需登录；用于换设备或恢复）。
- 同步内容包括但不限于：
  - 小说列表及各章正文、各章大纲；
  - AI 配置（厂商、模型偏好）；
  - **API Key**；
  - 其他前端约定的用户偏好。
- 未登录时隐藏或禁用上传/导入，并提示先登录。

#### 4.1.4 提示词模板

- 从后端拉取**固定模板列表**（按模式：章节 / 大纲 / 建议）；未登录时可用前端内置默认模板，登录后可刷新服务端模板。
- 用户选择模板后应用于当前对话模式；本地临时改写仅影响当次会话。

#### 4.1.5 设置页

- 注册 / 登录 / 登出入口；标明**不支持密码找回**。
- DeepSeek / Kimi Key 填写与校验（可选：发一条最小请求测通）。
- 默认厂商与模型。
- 上传 / 导入入口与状态提示（成功、失败、冲突）；未登录不可用。

### 4.2 后端

- 技术栈见 **1.4**：NestJS + SQLite；模块划分建议：`auth`、`sync`、`prompt-templates`。

#### 4.2.1 账号

- 注册、登录、登出（或 Token 失效）。
- 用户信息最小集：`id`、`username`、密码哈希、创建时间。
- **不提供**密码找回 / 重置接口。

#### 4.2.2 用户数据同步

- 接收用户全量数据上传并按 `userId` 持久化。
- 提供当前用户数据导出（供前端导入）。
- 数据中允许包含 API Key 字段；服务端**加密存储**，接口传输 HTTPS。

#### 4.2.3 提示词模板

- 维护固定模板（运营/开发在服务端配置，非用户随意增删）。
- 接口：按类型列出模板（id、名称、模式、内容、更新时间）。
- 模板列表可对登录用户开放；若需未登录也可拉模板，实现阶段再定（默认：有内置兜底即可）。

#### 4.2.4 AI 代理

- **本期不做**。AI 请求由客户端直连厂商。

## 5. 数据与同步规则

### 5.1 核心实体（逻辑模型）

```
User
  - id, username, passwordHash, createdAt

UserSecret / UserConfig
  - userId
  - deepseekApiKey (加密)
  - kimiApiKey (加密)
  - defaultProvider, defaultModel
  - preferences (JSON)

Novel
  - id, userId?, title, updatedAt
  - meta (可选：简介、类型等)
  # 全书级 outline 字段本期不采用；大纲落在 Chapter.outline

Chapter
  - id, novelId, title, order, updatedAt
  - content   # 正文章节（与 outline 分离）
  - outline   # 章大纲：对象或约定文本，须可单独提取/按范围拼接
    # 推荐：{ summary, beats[], notes, source, updatedAt }

PromptTemplate（系统级）
  - id, mode(chapter|outline|advice), name, content, enabled
```

**提取约定**：任何「丢给 AI 的大纲」均通过章节列表过滤 `order/id` 范围后，只序列化各章 `outline`（加章标题作锚点），禁止扫描 `content` 做大纲替代（除非用户显式选择「用正文摘要」且走自动维护流程）。

### 5.2 同步策略（首期）

- **全量快照**：上传 = 用本地快照覆盖云端该用户数据区；导入 = 用云端快照覆盖本地。
- 上传前二次确认：「将覆盖云端数据」。
- 导入前二次确认：「将覆盖本地数据」。
- 不做细粒度字段合并；可展示双方 `updatedAt` 供用户决策。

### 5.3 本地与云端一致性

- 日常读写以**本地**为准；上传/导入为显式操作。
- **未登录**：纯本地使用（配置 Key、生成、保存章节正文与章大纲）。
- **已登录**：可上传/导入；登出后本地数据默认保留，仅失去云端同步能力。

## 6. 页面结构（建议）

1. **小说列表**（未登录也可进入；设置里登录）
2. **工作台**：模式切换 + 对话区 + **大纲范围选择（注入 AI）** + 保存正文（自动维护大纲）/ 保存大纲
3. **章节列表 / 详情编辑**（正文与该章大纲分栏或 Tab；支持只读浏览/复制某范围大纲）
4. **设置**：Key、模型、账号（注册/登录/登出）、同步（上传/导入）
5. **登录 / 注册**（可从设置进入）

## 7. 非功能需求

| 类别 | 要求 |
|------|------|
| 安全 | HTTPS（后端）；密码哈希；API Key 服务端加密；同步接口鉴权 |
| 隐私 | Key 与正文仅对本人可见；日志脱敏；客户端直连时 Key 仅存于用户设备与本人云端包 |
| 可用性 | 弱网提示；厂商 API 错误可读提示；上传/导入可重试 |
| 性能 | 章节列表按需加载；单章体积过大时给保存提醒 |
| 多端 | 微信小程序 / H5 / App 共用业务层；分端差异收敛在适配层 |
| 合规 | **开发期暂不考虑**上架合规与用户协议 |

## 8. 验收标准（MVP）

1. 未登录即可配置 Key、直连 DeepSeek/Kimi 对话，并本地保存章节正文与章节大纲。
2. 可切换 DeepSeek、Kimi 及各自模型后成功生成。
3. 三种模式均可生成；大纲与正文分字段存储，可按章/范围单独提取并注入对话。
4. 保存正文后自动维护对应章大纲（可开关；失败不丢正文）；可手动改大纲。
5. 可手动注册、登录；**无**密码找回入口。
6. 登录后可将**含 Key 在内的全部用户数据**上传；清本地或换端后可导入恢复。
7. 未登录不能上传/导入；已登录用户数据互不可见。
8. 同一套 uni-app 工程可构建并跑通至少一端开发态，且工程具备微信小程序 / H5 / App 三端构建配置基础。
