# 清洗小说文本

分段原文保持不动。清洗结果只写到 `output/`。用户后续补充的规则追加到对应小节，并只对 `output/` 里的成书重跑该步骤。

默认用 PowerShell。读写使用无 BOM 的 UTF-8，保持原文件换行（一般是 CRLF）。标题相关的步骤可直接跑 `scripts/clean_titles.ps1`，见文末「脚本」。

## 合并

只处理文件名匹配 `书名(起始-结束章).txt` 的分段文件。`output/` 里的成书不参与合并。

1. 按括号前的书名分组。
2. 按正文里第一个章节标题的章号排序，不要按文件名里的章节范围排序。文件名范围经常和正文不一致。
3. 章节标题是行首的 `第N章`。`N` 可以是阿拉伯数字或中文数字（含「零〇两」）。
4. 每段开头是书名、作者、来源、网址、空行。成书只保留第一段的这 5 行，后续段删掉同样的开头。
5. 每段结尾是空行和 `更多精彩小说，请访问：速读谷 http://www.suduguu.com`。拼接前删掉各段的这段结尾。
6. 段与段之间留一个空行，再接下一章标题。
7. 全文末尾补两个空行和上述站点行，只出现一次。
8. 写成 `output/书名.txt`。
9. 合并后按「整章重复」检查分段范围是否重叠：范围重叠会在衔接处留下整章副本，章号也会跳回去。

PowerShell 函数若 `return` 一个 `List[string]`，调用方会得到展开后的 `Object[]`，后续 `AddRange` 会失败并写出空文件。在脚本内直接读写，不要把行列表从函数返回。

## 用字规则

对 `output/` 里的成书结合上下文检查，不把「幺」默认当作错字，不做全文无条件替换。本节取代原先「除老幺、幺蛾子外全部替换」的规则。

1. 保留「幺」的正常用法，包括「老幺」「幺蛾子」「幺弟」「幺妹」、数字读音、排行，以及人名、昵称、方言和专有名词，例如「竹幺妹」。不要只靠有限白名单决定其余「幺」都要替换。
2. 只有上下文明示是「什么」「怎么」「这么」「那么」等词的错写时，才逐处改成「么」。语境不明的保留，在聊天中说明疑点。
3. 修改前在当前会话中保留每处的章节或行号、原句和修改后句；完成后在聊天中逐项列出用字改动，便于核对和回退。没有用字改动也应说明。用户未要求时不另建日志或说明文档。
4. 复查历史清洗时，优先比对清洗前副本或逐处记录；没有记录时，只恢复上下文能确认的误改，不能把现有「么」批量反向替换为「幺」，也不能把推断当作已核实的历史改动。

## 错乱广告

## 重复标题

章节标题是行首的「第N章」，这一行本身没有缩进。若下一行去掉首尾空白（含全角空格）后与标题完全相同，删掉下一行。只处理紧挨着的这一行。

章号或标题文字不完全相同时，按下面三种情况处理。

### 带序号的标题

标题行可能带序号，如 `111.第111章 旷野，人是妈生的！`，紧接着还有一行 `　　第111章 旷野，人是妈生的！ `。序号 `111.` 不是标题的一部分，只按 `第N章` 取章号和标题文字，序号与章号不相等时也以 `第N章` 的 N 为准。

- 两行章号相同只留一行，写成不缩进、无序号、无行尾空白的 `第N章 标题`。
- 序号出现在 `第N章` 前面、两行章号相同，就是同一个标题被抄了两遍，不是两章。

### 截断或改写过的标题

同一章的两行标题文字不同时，不按位置决定留哪一行，按内容判断：

- 一行是另一行的前缀、明显被截断：约 20 字，或收在半截词、半个括号上，如 `第262章 转生成雨伞的我是不是搞错了什么（`、`第454章 妈，我和女朋友掉水里了你先救哪一`。保留完整的那一行。
- 站点改写造成的差异（`~`、`…`、缺字、大小写）：保留更完整、更干净的一行。例如 `FBIWarning：糖尿病慎入` 优于 `fbiwarning：尿病慎入`，`嘿嘿~嘿嘿~嘿嘿~` 优于 `嘿嘿嘿嘿嘿嘿`，`看我今日斩龙！` 优于 `看我…今日斩龙！`，`布布花，对谱尼使用寄生种子！` 优于 `布布，对谱尼使用寄生种子！`。
- 两行都坏（缺字、括号没闭合、结尾多个 `.`，如 `关于高一（四）班林立同学违.`、`…三十年俺不中嘞（求月票`）：保留较完整的一行，按原样留着，在聊天中逐条列出。不要自己补字、补括号或删标点。

### 章号不同的相邻标题

紧挨着的两行标题章号不同，如 `第237章 X` 后面跟 `　　第238章 Y`：

- 两行都留着，不删、不改号。
- 在聊天中列出章号和行号。这类位置通常伴随整章重复或正文缺失，按「整章重复」处理。

## 整章重复

合并或抓取时可能整章重复：同一段正文出现两次，两处标题行样式不同（一处 `第N章` 不缩进，一处 `　　第N章`）。

- 检测：同一章号出现两次且两段正文逐行完全相同；或连续两章（如 662、663）整段再来一遍。
- 正文逐行相同 → 删掉后出现的那一份，连同它的标题行；保留先出现的。正文里以空行分段，删的时候保留章末的空行，避免下一章标题贴在上文后面。
- 正文不同但有重叠（一章正文重复两次、下一章正文缺失）→ 不拼接、不改写、不改章号，记下章号和行号，报告给用户重新取这几章原文。
- 删除重复章节后再核对一遍章号序列。

## 章号校验

- 统计标题章号，`1..最大章号` 里缺的号如实报告，不补号、不重排。
- 同一章号出现两次但标题和正文都不同 → 多半是作者原文编号错误，两个都保留，报告。
- 衔接处章号倒退（如 647 之后又出现 646）→ 报告，不调换正文顺序。

## 校验

合并、标题或正文改动后确认：

- 成书只有一处书名头、一处站点尾。
- 衔接处是上一段末句、一个空行、下一章标题，章号没有在衔接处倒退。
- 逐处复核用字改动的上下文，正常的「幺」用法保持不变；聊天中的原句、修改后句和定位信息齐全。
- 错乱广告锚点在成书中没有残留。正文里的问号、感叹和正常句子还在。
- 章节标题的下一行不再是同一行去掉缩进后的重复。
- 每个章号只对应一行标题；章号本身重复的除外，但要报告。
- 所有标题行都不缩进、不带 `N.` 序号、没有行尾空白。
- 除标题行和被删掉的重复章节外，正文逐行与清洗前相同；只删标题时正文行数应完全一致。
- 站点行是最后一行；站点行之后还有 `--` 之类的残留就报告，不擅自删。
- 章号重复、缺号、章号不同的相邻标题，都已逐条报告。

## 脚本

`scripts/clean_titles.ps1` 处理「重复标题」整节和标题格式规范化，顺带检查整章重复、章号重复与缺号。

```powershell
# 默认写到 <源文件目录>\output\<书名>.txt，原文件不动
pwsh -File .agents/skills/clean-novel-text/scripts/clean_titles.ps1 -Source D:\novels\某书.txt

# 顺带删掉正文逐行相同的重复整章
pwsh -File .agents/skills/clean-novel-text/scripts/clean_titles.ps1 -Source D:\novels\某书.txt -RemoveDuplicateChapters
```

- `-OutDir` 换输出目录；`-Report` 换逐处改动记录路径，默认 `%TEMP%\title-clean-report.txt`。
- 只动标题行；正文、空行、换行符、无 BOM 一律原样保留。默认不动正文，`-RemoveDuplicateChapters` 只删正文逐行相同的整章。
- 跑完打印标题数、合并数、重复章节数、异常数，报告里逐条记录行号、原行和结果行。
- 脚本只报告、不处理的：章号不同的相邻标题、正文重叠导致缺章、章号重复与缺号。这些要在聊天里逐条告诉用户。
